## 总览

方案在**工程纪律(分阶段、隔离已商用主站、轻反馈不造假)**上很清醒,但五路审稿高度收敛地指出几个**根本性问题**,其中三个有代码实证。最尖锐的共识是:**现在不该进工程,应先用最低成本证伪 3 个致命假设。**

---

## 🔴 五路共识的硬问题

### 1. 蓝思中台 = 最危险的一步,第一版砍(教育+技术+红队)
- 蓝思是**阅读**难度标尺,口语 ≠ 阅读(接受性 vs 产出性技能;中国学生"读写强听说弱")。用阅读 band 派口语任务会**高估开口起点**,给"降焦虑"产品反向制造焦虑。
- **代码实证**:read 的 `PlacementTest.tsx` 是 **15 题(3轮×5题)、5 档启发式**,起始档用户自选,正确率 `correct/5` 决定升降档,档内线性插值出"蓝思值"——本质是穿 `###L` 外衣的 5 档粗分类器,代码自注释"不是精确分数""听力测评完善中"。
- 把它后端化、贴"科学分级·账号级"标签、写进**已商用主站 `profiles`(100+ 付费学员核心表)**,是把玩具量表焊上营销话术、把单点信任风险放大到三个产品。
- 事实勘误:`profiles.speak_activated` 字段**已存在**(`server/src/db/migrations/2026_04_24_speak_activated.sql`),方案不知道。
- **改**:第一版不做中台;口语起点与阅读蓝思**解耦**(默认 = 阅读 band − 1),加一道**真口语定级**(自由说一句 + 跟读 + 听后复述);删掉"读得懂 = 开口起点"的等式;绝不在此刻动主站 `profiles`。

### 2. "复用现成后端"被严重高估(技术+红队,代码实证)
- `/api/speaking/chat` = **无状态单轮代理**(多轮靠前端把全历史重发);**TTS 非流式**(`synthesizeWithWebSocket` 攒完整段才返回,`tts.ts` 注释写"流式"但代码是攒完再发);**每用户配额完全没有**(只有全局 IP 限流);**`enable_thinking:false` 在 speaking 路径缺失**(qwen3.x ~100s 超时雷,`writing.ts:225` 修过、speaking 漏了)。
- `estimated_tokens = aiMsgCount×150` 是写死猜测,Qwen 返回的真实 `usage` 没读 → 不知道真实成本。
- **改**:阶段0先修地基(补 enable_thinking、真实 token 计量、口语专属配额[轮次+TTS字符]+耗尽降级);做端到端延迟预算;多轮上下文加滑动窗口/摘要;TTS voice 真值源收敛到 `config` 一处。

### 3. iOS 资产被低估 —— 最难的一块其实做完了(技术+红队,利好)
- Speak-ios 已有 **~4650 行真原生 SwiftUI**:`SpeechRecorder.swift`(已和 iOS26 `AVAudioEngine` 僵尸引擎 bug 搏斗、**回退成文件式 `SFSpeechURLRecognitionRequest`**、有 benign 错误降级)+ `PronunciationScorer.swift`(词级 Levenshtein 打分,即"轻反馈三件套"第2件已实现)+ 已接入 `PracticeScreen` UI。
- 方案基于**过时 README**,把已做完的当新工作(§6 待确认③应在写方案前做)。
- **关键含义**:ASR 已是**文件式非流式** → §3.6"实时纠错/实时支架"在现有可靠实现上**不成立** → 改成"**整句说完 → 反馈**"(更贴低压定位)。
- 盲点:iOS 当前**无网络层 + mock 登录**,阶段1"复用后端"要从零建客户端通信层(HTTP/JWT/Keychain/TTS播放/重试)——最大的隐藏工作量。

### 4. 定位矛盾:"降焦虑" vs "考核式自由对话"(产品+教育+红队)
- 任务清单 KPI + curveball 随机刁难 + 任务达成/失败判定,对开口焦虑孩子是**焦虑放大器**(怕说错/被评判/冷场三件全做满)。
- 任务清单"逐个点亮"诱导**清单触发式背诵** → **假流利(scripted speech)**,迁移率低 —— 这正是"背了无数对话还是不会说"的机制。
- **改**:主线改**半开放、有句卡轨道的对话**(照推荐句也能轻松走完一局、被 Rosie 夸,脱稿自由说作进阶);任务清单**软化为隐式**(留到对话后回顾);A2 砍 curveball/KPI;同场景**变式复现**(第二次换问法/换 curveball)对抗背诵;对话末留一个**自由产出**出口。

### 5. 商业空白 + 没验证需求(商业+红队+产品)
- 方案全是供给侧,没回答:**家长为什么付费 / 首批 100 付费用户从哪来 / 按量烧钱怎么不亏**。
- AI 口语陪练正被大厂**免费**碾压(豆包/星火/Kimi/多邻国 Max)——`AI 陪聊`是大模型原生能力,**不能当卖点**;能守的只有蓝思+中考听说应试+read内容联动+本土家长信任。
- read×speak 协同排到**阶段3** = 先上线的是无差异套壳,**护城河被排最后**。
- 口语是**按量变动成本**,"永久档"是定时炸弹(read 的内容型永久买断经验不能平移)。
- "Rosie IP"目前只是声线+定妆照,**最易被复制那层**,短期别算进护城河。
- 政策:绑"中考听说应试"更近教培红线,营销话术要克制、收费周期别超 3 个月。
- **改**:补"家长成果交付物"(开口月报+最佳录音集,把过程固化成可炫耀资产)+ 应试锚点(中考英语听说)+ 单位经济模型;慎用永久档;read 联动前移到阶段1(最薄版:read 文章→配套口语任务);重新定位 speak 为 **read 的增值/续费模块**而非独立新品类。

## ✅ 五方一致确认"对"的决策(别动)
1. **不上声学评测、轻反馈先验证留存**(教育低压 / 商业克制 / 技术务实 三方认可)——全方案最清醒的一刀。
2. **分阶段、隔离已商用主站、依赖最重的 read 放最后**(工程纪律对;但商业上护城河排最后是错的,见 #5)。
3. **iOS 优先 + 跟读音频预生成**(原生 ASR 远胜 WKWebView;预生成是控成本/控延迟最大杠杆)。

## 🎯 最强共识:先验证,再开发(一行产品代码都不用写)

| # | 要证伪的假设 | 最小验证 | 不通过的后果 |
|---|---|---|---|
| 1 | 孩子(非家长)会持续开口 | 拿**现有 iOS app**(已能真录真评)给 15-20 个真实目标孩子用 2 周,只看 **D7 开口留存** | <30% → 陪练做再深也救不回,产品逻辑重想 |
| 2 | 家长会为 AI 口语付费 | read/主站用户里放"读说一体·口语陪练"**预约/预付/留资**入口,看真金白银意愿 | 意愿低 → 降级为 read 增值模块,别独立做 |
| 3 | 蓝思量表准 + ASR 听得懂中式发音 | 同批孩子测评对比**真人老师独立定档**一致率;录中式发音测 `SFSpeechRecognizer` 词级准度 | 一致率<70% → 中台叙事推翻;准度<85% → 轻反馈系统性误判,要重想 |

> 纪律:这三件**全部用现有资产、不写产品代码、1-2 周可完成**。当前方案是"先建地基再验证",正确顺序是**先证伪再决定建不建**。

## 行动清单(方案必改项,优先级)

1. **【动工前】先做上面 3 个验证**(尤其 ② 付费意愿——成本几乎为零、ROI 最高)。
2. **砍蓝思中台出第一版**;口语定级解耦 + 真口语定级;绝不动主站 `profiles`。
3. **主线改半开放轨道对话**;软化任务清单为隐式;A2 砍 curveball/KPI;变式复现 + 自由产出出口。
4. **交互改"整句轮次反馈"**(对齐已落地的文件式 ASR);先盘点 iOS 资产再重排路线(已做完的从"新建"改"接线")。
5. **补技术地基**(阶段0):enable_thinking、真实 token 计量、口语配额+降级、iOS 客户端网络层、端到端延迟预算。
6. **补商业**:成果交付物(开口月报)+ 应试锚点(中考听说)+ 单位经济;慎用永久档;read 联动前移阶段1;重定位为 read 增值模块。
7. **教育颗粒度**:预学加输入冗余(8-12句+跟读2-3遍+提取练习);发音用最小音位对立(minimal pairs)听辨真做一点(零评分引擎);AI 点评别基于 ASR 假装评发音;纠错加"重说一次(uptake)"闭环;补听力解码训练。
